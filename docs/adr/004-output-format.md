# ADR 004 - Output format: JSON v1 with stable schema

- **Status**: Accepted.
- **Date**: 2026-05-20.
- **Authors**: Zierax.

## Context

The first prototype emitted a custom text format that was
machine-parseable in theory and a nightmare in practice.  An
operator who wanted to load findings into a spreadsheet had to
write a parser.  An operator who wanted to feed findings into
a SIEM had to write another parser.

## Decision

Adopt JSON as the canonical output format.  Define a single
schema, `z-privesc.audit/v1`, and bump the version suffix on
breaking changes.  The HTML emitter is a presentation layer
over the same JSON, generated by the same audit context.

The schema is documented inline in the audit emitter and in
the README.  A future release may add SARIF 2.1 as an additional
format (see ROADMAP.md); it will not replace JSON.

## Consequences

- The JSON output is stable across patch versions.  Adding
  fields is allowed; renaming or removing fields is a breaking
  change and bumps the schema version.
- `jq` works out of the box for ad-hoc operator queries.
- The audit emitter is the only place that knows about the
  schema; everything else operates on the in-memory audit
  context.
- The HTML emitter depends on the JSON emitter's field set;
  when a field is renamed, both must change.
